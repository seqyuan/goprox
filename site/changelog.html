v0.13.0 — 2026-11-09（日志落盘）

  • /logs 历史持久化：事件写入 <配置目录>/logs/events-YYYY-MM-DD.jsonl（每日一个文件），默认保留 7 天并自动清理；网关重启后历史仍在。
  • 三个开关：server.log_retention_days 取 1–3650；0 = 只存内存（不建目录）；缺省 7；越界启动报错。goprox check 会打印日志目录与保留天数。
  • 稳健性：读取按天文件从新到旧聚合（单文件最多 8 MB）；崩溃留下的半行 JSON 自动跳过；日志目录不可写时告警并退回内存模式，网关照常运行。
  • 安全：盘上只记录账号 / 类型 / 卡片 / 结果 / 原因 / 耗时，不含密码、Cookie 或后端响应体；文件权限 0600、目录 0700；页面与 API 仍只返回本人记录。

v0.12.0 — 2026-11-07（日志页与卡片体检）

  • 每用户日志页 /logs（账号菜单入口）：登录（成功 / 失败原因）、卡片访问（成功 / 失败 / 耗时 / 原因）、连通性检测结果；服务端渲染，前端资源坏了也能看；另有 GET /api/logs?limit=N 返回 JSON。只显示本人记录，不引入管理员角色。
  • 卡片「测一下」/「全部测一下」：只读探测（代理卡片 3 秒 TCP 连接、文件卡片检查目录可读），状态灯 灰/黄/绿/红 + 悬停原因；POST /api/services/{id}/probe。可用来回答「这张卡片到底通不通、为什么不通」。
  • 记录策略：每账号 500 条内存历史，重启清空；静态资源（JS/CSS/图片）不记录；登录失败只对已存在账号记录，避免随机用户名撑大内存；探测仍受私网 allowlist 约束。

v0.11.0 — 2026-11-07（同主机多实例隔离）

  • auth.cookie_suffix：浏览器按主机（忽略端口）存 Cookie，同主机多个 goprox 会互相覆盖 session / 2FA / route Cookie。配置后缀后每个实例使用 goprox_session_<suffix>、goprox_2fa_<suffix>、goprox_2fa_setup_<suffix>、goprox_route_<suffix>；默认空值保持历史命名，升级无感。
  • 读写路径全部按实例命名（登录/续期、2FA pending/setup、route）；退出只清理本实例 Cookie，不会把同主机另一实例的用户登出；网关 Cookie 仍按 goprox_ 命名空间整体从后端请求剥离。
  • 非法后缀（非 [A-Za-z0-9_-]{1,32}）启动即失败，不静默回退；goprox check 输出生效后缀；配置后缀后该实例用户需重新登录一次。
  • serve 启动路径可测化：拆出 startGateway（返回 error）+ gateway.run/serve，新增明文启动/登录页/监听持久化、--tls-selfsigned 真实 HTTPS 与重启复用证书、vhost 配置不全、端口占用、非法 CLI 值等集成测试；main 覆盖率 40.6% → 50.9%。

v0.10.0 — 2026-11-07（用户级文件权限）

  • 按用户的文件浏览白名单：用户 YAML 顶层 files_roots，在该用户的文件卡片上再收一层（与 server.files_roots 取交集，按 EvalSymlinks 判断，符号链接逃逸拒绝）。仪表盘 / API 不读写该字段，用户无法自我放宽；列表非法时该用户文件卡片全部停用（失败即关闭）。
  • 网关级挂载白名单：server.files_roots 限制所有 kind: files 服务可用的目录；非法条目启动即报错，goprox check 输出生效白名单。
  • 暴露面提醒：监听 0.0.0.0/:: + 纯 HTTP + 未配置 trusted_proxy 时，启动日志打印明确 WARNING（不阻塞启动）。
  • 旧密码哈希自动升级：登录成功时把旧版 SHA-256 就地重写为 bcrypt，无需手动重置；配置不可写时只记日志。
  • 可维护性与测试：server.go(1586) 拆为 4 个领域文件、config/user.go(1051) 拆为 3 个、main.go(753) 拆为 5 个（纯搬移）；新增 ci.yml（push/PR 跑 gofmt + vet + go test -race）；main 包覆盖率 22.7% → 40.6%。
  • 文档：四份 2026-07 历史报告移入 docs/archive/；2026-11-07 项目审查收入 docs/reviews/ 并附逐条核验与处理状态。

v0.9.1 — 2026-11-07（安全修复）

  • 禁止文件浏览挂载网关配置目录：kind: files 的 root 若等于 / 包含 / 位于配置目录内（含符号链接，按 EvalSymlinks 解析后判断）一律拒绝——配置加载时跳过并告警，仪表盘 / API 返回可读错误。
  • 修复的利用链：v0.9.0 中任意登录用户可把配置目录挂成卡片，下载 state.yaml 的 session_secret 与 users/*.yaml 的密码哈希 / TOTP 密钥，进而离线伪造任意账号会话。
  • 升级建议：v0.9.0 用户请尽快升级；升级后指向配置目录的卡片会被跳过，需把 root 改为具体数据目录（如 /data/share）。
  • README 补充文件浏览服务的权限边界与最小权限部署建议（专用账号 + ACL / systemd 加固）。

v0.9.0 — 2026-11-07（内置文件浏览服务）

  • 新服务类型 kind: files：卡片只填一个本机目录，网关自己当后端——目录列表、单文件内联预览（图片/PDF/音视频/纯文本）或附件下载，无需再起静态服务。
  • 目录 ZIP 打包下载：列表页「下载全部（ZIP）」（?zip=1）流式生成，不留临时文件；单文件支持 Range 续传与 bwlimit 限速。
  • 只读与隔离：无上传/删除/重命名，写方法一律 405；os.Root 拒绝 .. 与逃逸符号链接；内联响应统一 CSP: sandbox + nosniff，HTML/SVG 只能下载；跨用户 404。
  • 仪表盘与 API：「服务类型」下拉 + 目录路径 / 显示隐藏文件；/api/services 支持 kind / root / show_hidden，proxy ⇄ files 切换带校验。
  • 重定向修复：Location 指向本机任意地址写法（局域网 IP / 回环 / 通配）且端口一致时视为同一后端；无路径的绝对重定向映射到服务根；保留 #fragment。修复「跳转后地址栏变成 192.168.x.x:端口」。
  • 本机后端地址归并：host 填本机局域网 IP / 0.0.0.0 / localhost 且回环可连时统一按 127.0.0.1 处理，避免发夹路由；只绑局域网网卡时保留原值，YAML 不改写。
  • 文档：README 新增「host 到底填哪个地址」「配置模式怎么选（含排障速查）」「文件浏览服务」三节。

v0.8.2 — 2026-10-24（安全与稳定性修复）

  • 网关 Cookie 命名空间隔离：转发前剥离所有 goprox_* Cookie，后端也不能再设置该命名空间；修复 2FA setup Cookie 携带明文 TOTP 密钥泄漏、default_service 裸路径下后端覆盖 session/route Cookie。
  • 登出改为 POST-only：GET /logout 只显示确认页；POST 校验 Origin，并清理 Domain/host-only session、2FA 临时 Cookie 与全部 route Cookie，消除跨站登出 CSRF。
  • 2FA 令牌绑定：setup token 绑定用户、pending token 绑定密码 rev；改密后未完成的二次验证失效，共享浏览器不能跨账号绑定。
  • Referer / 转发头 / XFF 加固：Referer 路由要求同 authority；覆盖 X-Real-IP，清理 Forwarded / X-Original-URL / X-Rewrite-URL 等；XFF 从右向左取非可信跳点。
  • vhost / path 边界：未登录 vhost API 返回 401；跨用户 path 返回 404；HTTPS 网关下 Origin 使用后端 http scheme。
  • 监听配置持久化修复：--host / --port 仅在显式传参时覆盖 state.yaml，重启不再被默认值重置或意外暴露到所有网卡。
  • 配置原子写 + 临时锁：temp + fsync + rename；O_EXCL 临时锁正常释放即删除、崩溃遗留按 PID/mtime 回收，兼容不支持 flock 的 NFS。
  • 用户与 registry：goprox user 原子创建、del 锁内删除；首次运行自动建 users/；扫描失败不再每请求重扫；session rev 查询加缓存。
  • 上传与限流：代理上传改为空闲读超时，不再被 60s 总时长中断；限流饱和时保护在途 key，新 key 仍能进入封禁。
  • 路由修复：ForwardAsIs 重定向不再加 /proxy/ 前缀、vhost/as-is 支持 auth_bootstrap、非 GET 裸路径直接转发、favicon 不覆盖最近服务、backend_path 段边界、IPv6 authority、root service 子路径等。

v0.4.1 — 轻量级单点登录（SSO）

  • 轻量级 SSO：goprox sso 开启后，网关把登录用户名以请求头形式带给所有被代理的后端（如 X-Authenticated-User: alice），后端信任该头即可免登录识别用户——个人 Jupyter / RStudio / dsh 无需各自登录。可选 --hmac-secret 共享密钥：同时下发 user_header-Signature（HMAC-SHA256，base64url），后端验签后不再依赖网络隔离。配置持久化到 state.yaml 的 sso 段，重启生效。
  • 身份头防伪造：网关始终覆盖（而非透传）客户端传入的身份头，并无条件剥离 X-Authenticated-User / X-Forwarded-User / X-Auth-Request-User / Remote-User / Remote_User 等常见身份头——即使 SSO 未开启，浏览器也无法通过这些名字冒充用户。
  • 安全约束：后端必须只能经网关访问（回环/防火墙）；无法网络隔离时必须使用 hmac_secret 签名。详见安全页面。
