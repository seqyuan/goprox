认证与公网部署

密码存储、会话机制、可选的 TOTP 两步验证，以及暴露到公网前必须做的 TLS。

密码存储

密码使用 bcrypt 哈希（goprox user / goprox passwd 生成）。 旧版本遗留的 SHA-256 哈希仍可正常登录（自动兼容），建议在方便时用 goprox passwd 重置一遍。

配套防护：

  • 登录限速：按「客户端 IP + 用户名」限速（10 次失败/15 分钟），共享 NAT 下互不影响；
  • 时序防枚举：未知用户名也执行等价的 bcrypt 比对，登录耗时无法暴露账号是否存在；
  • 改密即吊销：会话绑定密码哈希版本，改密码后所有已签发会话立即失效；
  • CSRF 防护：管理 API 与登录接口校验 Origin 头，跨站请求被拒绝。

两步验证（TOTP，可选）

暴露到公网时，强烈建议为账号开启基于时间的一次性密码（TOTP）二次验证。 按用户可选，开启后登录需要密码 + 认证器 App 显示的 6 位动态码。

开启 / 更换（用户自助，登录后操作）

  1. 登录仪表盘，点顶部提示中的「两步验证未开启 · 开启」链接；
  2. 用手机认证器 App（Google Authenticator / Authy / 1Password）扫描二维码，或手动输入密钥；
  3. 输入 App 当前显示的 6 位动态码，确认后即生效。

登录流程（开启后）

密码正确 → 输入 6 位动态码 → 进入仪表盘。

手机丢失 / 忘记

管理员在服务器上执行（无需登录）：

goprox 2fa-reset <用户名>
密钥以 base32 形式存在 config/users/<用户名>.yaml 的 auth.totp_secret 字段（权限 0600，与 session_secret 同级保护）。 动态码校验带有 ±1 个 30 秒窗口的时钟容错，且同样受登录限速保护。

公网部署：反向代理终结 TLS

把 GoProx 暴露到公网前，必须有 HTTPS：要么用 v0.4.0 的原生 TLS （--tls-cert/--tls-key，或 --tls-selfsigned 自签）， 要么在网关前放一个反向代理终结 TLS（本节）。需要先给 GoProx 提供 TLS 时用原生 TLS； 已有 Caddy/nginx 时用本节的反代方案。Cloudflare 隧道（cloudflared）对接见 隧道对接。 无论哪种方式，公网上的密码（以及动态码）都必须走 TLS 加密传输。

1. 让 GoProx 只监听本机回环

./goprox serve --host 127.0.0.1 --port 1908 \
  --trusted-proxy 127.0.0.1/32
  • --host 127.0.0.1：只监听回环，只有本机的反代能连到它；
  • --trusted-proxy 127.0.0.1/32：信任来自回环的 X-Forwarded-For/Proto 头， 让网关正确识别「真实客户端 IP」（登录限速用）和「请求是 HTTPS」（Secure Cookie 用）。
trusted-proxy 必须填反代所在地址，不能填 0.0.0.0/0 （那样任何直连客户端都能伪造 X-Forwarded-* 头，绕过限速、伪造 Secure Cookie）。

2. Caddy（推荐）

# /etc/caddy/Caddyfile
lab.example.com {
    reverse_proxy 127.0.0.1:1908
}

Caddy 会自动转发 X-Forwarded-For / X-Forwarded-Proto，并自动申请、续期 HTTPS 证书。

3. nginx

server {
    listen 443 ssl;
    server_name lab.example.com;

    ssl_certificate     /etc/letsencrypt/live/lab.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/lab.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:1908;

        proxy_set_header X-Forwarded-For   $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host  $host;

        # WebSocket（Jupyter / RStudio 必需）
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}

证书可用 certbot 申请：sudo certbot --nginx -d lab.example.com。

4. 验证

curl -I https://lab.example.com/login     # 应返回 200，且证书有效

登录页在浏览器里应有正常的小锁图标（HTTPS），且登录后的 Cookie 带有 Secure 标记。 完整的配置文件示例见仓库 docs/reverse-proxy-tls.md。
