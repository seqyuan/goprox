# 独立域名虚拟主机（hostnames）配置指南

> 适用版本：v0.8.0+（Phase 1）。
> 默认关闭；未配置 `hostnames` 时行为与旧版本完全一致。

## 1. 适用场景

服务需要真正拥有自己的 Origin 和根路径时使用：

- 应用输出 `/docs/`、`/static/...` 等根绝对路径，且不能改 `baseURL`；
- 应用把 `/` 当作自己的首页；
- 不想依赖 `/proxy/<用户>/<服务>/` 前缀、`default_service` 或 `root_absolute`。

如果只是普通子路径应用，继续用 `path`；如果能改应用 `baseURL`，优先改应用。

## 2. 快速开始

### 2.1 网关状态

编辑 `config/state.yaml`：

```yaml
server:
  host: "0.0.0.0"
  port: 30152
  public_host: "gw.example.com"     # 主网关对外地址；非标准端口写 host:port
  public_scheme: "https"            # http 或 https
  cookie_domain: ".example.com"     # public_host 和所有 hostnames 都必须在它下面
  trusted_proxy: "127.0.0.1/32"     # 仅当前面有反向代理时设置
auth:
  session_secret: "<auto-generated>"
  session_ttl: 86400
```

也可以启动时写入：

```bash
./goprox serve --public-host gw.example.com --public-scheme https --cookie-domain .example.com
```

### 2.2 服务配置

编辑 `config/users/<用户名>.yaml`：

```yaml
services:
  - id: hugo
    name: Hugo 预览
    host: 127.0.0.1
    port: 1313
    path: /hugo              # 仍可用于 /proxy 路径访问
    hostnames:
      - hugo.gw.example.com
    websocket: true
```

重启网关。也可以直接在仪表盘「编辑 → 高级」中填写 `hostnames` / `root_absolute`；
`/api/services` 同样支持这两个字段。`hostnames` 的第一个域名会作为卡片上的
「独立域名」入口（顺序会被保留）。

`goprox` 会：

- 校验 Host 语法、跨用户冲突、`public_host`/`hostnames` 是否被 `cookie_domain` 覆盖；
- 校验 `public_host` 不能同时是某个服务的 Host；
- 启动日志输出虚拟主机数量/告警。

### 2.3 登录

首次访问：

```text
https://hugo.gw.example.com/docs/
→ 302 https://gw.example.com/login?next=https%3A%2F%2Fhugo.gw.example.com%2Fdocs%2F
→ 登录成功
→ 302 回 https://hugo.gw.example.com/docs/
```

登录后会话 Cookie 带 `Domain=.example.com`，浏览器会把它发给所有子域。

> 启用 vhost 后，旧的 host-only 会话需要重新登录一次；登录时会自动清除旧的
> host-only 同名 Cookie。

### 2.4 配置预检

不启动服务，直接检查 state/users/虚拟主机：

```bash
./goprox check -d /path/to/config
```

输出示例：

```text
[goprox] public_host: "gw.example.com"
[goprox] cookie_domain: ".example.com"
[goprox] users: 2, services: 5, virtual hosts: 3
  hugo.gw.example.com -> alice/hugo
  ...
[goprox] config check OK
```

冲突或 `cookie_domain` 覆盖错误会让命令以非零状态退出。

### 2.5 本地测试

建议使用 `.test` 域名 + hosts/DNS，不要使用 `*.localhost`：Chrome 会拒绝
`Domain=.localhost`，父域会话 Cookie 无法建立。

在 `/etc/hosts` 增加：

```text
127.0.0.1 gw.example.test hugo.example.test
```

配置：

```yaml
server:
  public_host: "gw.example.test:30152"
  public_scheme: "http"
  cookie_domain: ".example.test"
services:
  - id: hugo
    host: 127.0.0.1
    port: 1313
    path: /hugo
    hostnames:
      - hugo.example.test
```

访问 `http://hugo.example.test:30152/`。Playwright/Chromium 也可以用
`--host-resolver-rules=MAP *.example.test 127.0.0.1` 代替 hosts。

注意本地 HTTP 仅用于测试，生产必须 HTTPS。

## 3. DNS 与 TLS

### 3.1 通配 DNS

```text
*.gw.example.com → 网关或反向代理 IP
```

也可以为每个 `hostnames` 建独立的 A/CNAME。

### 3.2 Caddy（推荐）

```caddyfile
*.gw.example.com {
    reverse_proxy 127.0.0.1:30152
}
```

- 通配证书通常需要 DNS challenge；
- Caddy 自动转发 `X-Forwarded-For` / `X-Forwarded-Proto`；
- GoProx 设置 `trusted_proxy` 为 Caddy 地址，`public_scheme: https`。

### 3.3 nginx

```nginx
server {
    listen 443 ssl;
    server_name *.gw.example.com;

    ssl_certificate     /path/to/wildcard.pem;
    ssl_certificate_key /path/to/wildcard.key;

    location / {
        proxy_pass http://127.0.0.1:30152;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

GoProx 侧设置 `trusted_proxy: 127.0.0.1/32`。

### 3.4 GoProx 原生 TLS

现有 `server.tls_cert` / `tls_key` 可以直接使用一张 `*.gw.example.com` 通配证书。
GoProx 对所有 SNI 返回同一张证书，覆盖一级子域。

`--tls-selfsigned` 生成的自签证书只覆盖 localhost + 局域网 IP，不适合 vhost 域名；
vhost 请使用通配证书或外部 TLS 反代。

## 4. 请求语义

```text
https://gw.example.com/          → GoProx 仪表盘 / 登录 / 服务管理
https://hugo.gw.example.com/     → Hugo，路径原样转发
https://hugo.gw.example.com/docs/→ Hugo /docs/
```

- 服务 Host 上**所有路径**（包括 `/login`、`/api`、`/logout`）都归应用；
- GoProx 管理入口只在主 Host；
- 未登录访问服务 Host → 主 Host 登录 → 回到原 URL；
- 用户不匹配 → 404（不泄露 Host 是否存在）；
- vhost 模式不设置 route cookie；
- 后端 Cookie 保留原 Path；与 GoProx 同名的后端 Cookie 会被丢弃；
- `Location` 不再加 `/proxy` 前缀；
- `X-Forwarded-Prefix` 为空；
- SSO、WebSocket、带宽限制、`auth_bootstrap` 继续生效。

## 5. 配置模式选择

| 场景 | 推荐配置 |
| --- | --- |
| 普通应用，能接受 `/proxy/<用户>/<服务>/` | `path` |
| 后端自身有子路径 | `path` + `backend_path` |
| 根路由型 SPA（按 `window.location.pathname` 匹配 `/...`） | `default_service` |
| 输出根绝对路径，但不能改 `baseURL` | `root_absolute` |
| 应用必须拥有独立 Origin / 根路径 `/` | `hostnames` |
| 同一主机多实例 | 不同父域/主机名；或使用 Cookie 命名空间方案 |

关系说明：

- `hostnames` 最彻底；`root_absolute` 是轻量兼容层；
- 同时配置 `hostnames` 和 `root_absolute` 时，vhost 请求走 vhost；`root_absolute`
  只影响主 Host 的裸路径；
- `hostnames` 与 `default_service` 相互独立：vhost 处理服务 Host，默认服务处理主 Host
  的裸路径；
- `hostnames` 与 `path` 可以并存：主 Host 仍可按 `path` 访问；
- `hostnames` 与 `backend_path` 可以并存：vhost 路径仍会拼接 `backend_path`。

## 6. 排障

| 现象 | 排查 |
| --- | --- |
| 登录后又回登录页 | `cookie_domain` 是否覆盖 `public_host` 和服务 Host；是否使用 HTTPS；是否通过 `public_host` 访问主网关；旧 host-only Cookie 是否清除 |
| 服务 Host 返回 404 | 该 Host 是否被多个用户/服务声明（启动会报错，reload 日志会打印）；是否在 `cookie_domain` 下；服务是否被删除；当前登录用户是否匹配 |
| 登录后跳到 `/` 而不是服务 | `next` 的 scheme/端口与 `public_scheme` / `public_host` 不一致；检查 `public_host` 是否包含非标准端口 |
| 后端 Cookie 没出现 | 后端 Cookie 名是否与 `goprox_session`/`goprox_2fa*`/`goprox_route*` 冲突（会被丢弃）；`Domain` 会被丢弃，`Path` 保留 |
| WebSocket 403 | 服务的 `websocket: false`，改为 `true` |
| 主 Host `/hugo/...` 仍跳 `/proxy/...` | 这是保留的路径模式行为；vhost 是独立入口。Phase 2 可评估改为跳 vhost |
| 浏览器提示证书错误 | 通配证书是否覆盖该级别（`*.example.com` 不含 `a.b.example.com`）；自签证书是否覆盖域名 |
| `*.localhost` 登录后仍无会话 | Chrome 拒绝 `Domain=.localhost`；改用 `.test` 域名 + hosts/`host-resolver-rules` |

## 7. 限制与安全

- 必须使用 HTTPS；父域会话 Cookie 会发送到所有子域。
- `public_host` 和所有 `hostnames` 必须被 `cookie_domain` 覆盖。
- `cookie_domain` 必须是自己的父域，不能是 `.com`、`.co.uk` 等公共后缀。
- 同一父域下运行多个 GoProx 实例时，会话 Cookie 名仍会冲突；需要不同父域或
  后续 Cookie 命名空间方案。
- 服务 Host 拥有所有路径；如果应用需要 GoProx 的 `/api/services` 等管理接口，
  请使用主 Host。
- 不使用 vhost 时，`root_absolute` / `default_service` / 路径代理仍然可用。
- 生产升级前建议先备份 `config/`，并在维护窗口重启（`public_host`/`cookie_domain`
  变更需要重启，`hostnames` 由 10 秒扫描热加载）。
